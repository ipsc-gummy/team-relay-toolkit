# 部署与配置范围

本仓库是从专用团队部署整理的模板。部署脚本具有真实的系统修改能力；先读源码并明确目标主机。不会替你提供服务账号、上游登录或团队凭据。

## 服务端

目标环境是 Linux x86_64、OpenSSH、systemd、Python 3.11+，统计部署另需 `requirements-dev.txt` 中的 PyYAML 与 bcrypt。

`程序/install.sh` 保留固定 CLIProxyAPI 版本与发行包校验。执行者必须显式指定预期主机名；现有目标目录或服务存在时应停止，不能用它覆盖正在工作的实例。历史固定版本不构成当前最新版或安全性保证。

服务只应监听回环地址。样例使用 `203.0.113.10`，它是文档保留地址，不对应本项目的真实服务器。部署者需要审阅并一致配置以下位置：

1. `程序/App切换/切换CodexApp.py` 的服务器地址、SSH 端口及信任锚点。
2. `程序/新人一键接入/一键接入.py` 的固定主机公钥。
3. `程序/打包新人两步接入.py` 生成的成员 manifest。
4. 服务器 SSH Match / PermitOpen 与 CLIProxyAPI 回环端口。
5. 当前 Codex App 的实际后台程序路径与 app-server 协议。

发布副本里的公钥来自 RFC 8032 公开测试向量，指纹为 `SHA256:bbXpuKG6zhzdmnxq256TlqzFBzRl2f6OOg722cYNbU8`。它只用于隔离测试，不能作为真实服务器信任锚点。

## 成员接入

成员先生成或识别本人专用密钥，只交付公钥和指纹。管理员开通受限身份后，再用打包器为该成员生成个人包。不要把个人包、私钥、Token 或认证状态上传 GitHub。

`新人接入` 下的说明是部署后的交付模板，不是任何现成服务的邀请链接。缺少真实 manifest 或凭据时，安装入口应停下，不应猜测身份。

## Windows

SSH 后台隧道由本人普通 Windows 用户运行。Agent 沙箱可能限制联网、读取私钥或访问 SSH agent，诊断时必须区分运行身份和权限。不能把沙箱失败直接归结为服务器断线，也不能通过删除全部 ACL 或整体关闭沙箱来规避检查。

完成配置后，应分别验证宿主机 SSH、带鉴权的模型接口、App 新对话、个人模式恢复，以及经本人同意的断线恢复。只看到端口监听或 CLI 成功不代表 App 已通过。

## 回滚

部署前保留当前有效状态的私有备份。客户端配置事务负责原子写入、字段校验与失败恢复；遇到未知占用、并发变化、损坏状态或真正协议不兼容时，应停止并报告，而不是不断覆盖状态。
