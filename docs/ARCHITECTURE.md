# 架构与原创边界

## 数据流

客户端把模型请求发往本机回环端口，OpenSSH 将字节流转发至服务器回环地址上的 CLIProxyAPI。代理处理配置的上游认证并转发请求，响应沿原路返回。

服务器的统计服务独立消费管理用量事件，以成员 Key 的本地映射确定归属，只保留事件标识、时间、模型、token 计数、失败状态和质量信息。本人查询根据服务器识别的 Linux UID 决定目标成员，不接受任意用户名作为查询身份。

## 控制面

- 开通器创建受限成员并登记成员公钥，建立受限转发与本人查询入口。
- 打包器按显式白名单生成两步说明及个人接入文件；真实个人包含凭据，不能提交到仓库。
- 客户端维护器管理自己的后台 SSH 子进程，协调端口、锁和重连。
- 配置切换器只管理约定字段，保留个人登录及无关配置。
- 管理员路由代理适配 app-server 的任务开始、恢复、分叉和后续轮次，不编辑历史数据库来伪造路由。
- 自愈模块从独立 canonical 定义恢复受管 provider，使用实际协议兼容检查、原子写入、并发检查和有保留数量上限的备份。

## 明确不属于本仓库的能力

CLIProxyAPI 的 OAuth 流程、认证刷新、上游请求转换和事件生产；OpenSSH 的加密与密钥认证；Codex 的模型、官方 app-server 及客户端执行沙箱，均属于外部依赖。

## 隐私与可见性

SSH 保护客户端到服务器的链路，上游 HTTPS 保护服务器到模型服务的链路。代理管理员在技术上可以接触经代理处理的内容；不能把这个部署描述为对代理管理员端到端保密。

本仓库的统计设计不把 prompt、上下文或原始 API Key 写入统计数据库。该设计不自动证明所有外部组件的日志行为，部署者还需核对实际代理日志配置。

## 工程成熟度

隔离回归可以证明指定代码路径在测试替身上的行为，不能替代新版 App、真实网络和 Windows 桌面的实际验收。旧成员电脑上可能仍安装不同版本，因此发布源码与成员现有状态需要分别核验。
