# 第二步：交给本机 Agent 接入 · 团队中转

公开仓库中的 `203.0.113.10`、`relay.example.invalid` 及主机指纹均为示例。指纹来自 RFC8032 公开测试向量，绝不能用于真实部署。管理员须先将客户端、打包器和说明中的目标地址及固定公钥/指纹替换为自行核实的真实配置，再生成个人包。以下操作只适用于已完成配置的包。

管理员确认开通后，把**本人 Windows 个人包**交给可信的本机 Agent，发送：

> 请读取包内第二步全文，按附录完成已有安装检查、必要修复和 Codex App 验收。保留我的登录、历史和原配置，不输出密钥。需要我操作时只给一条明确命令，不要让我重新完整安装。

首次由 Agent 配置一次。日常在普通 PowerShell 执行一行，再**完整退出 Codex App（包括托盘），重新打开、新建对话**：

~~~powershell
& "$HOME\Codex团队接入\接入.cmd" team
~~~

这是示例团队入口，会检查或启动本套 SSH 后台连接。返回本人 ChatGPT 账号：

~~~powershell
& "$HOME\Codex团队接入\接入.cmd" personal
~~~

末尾改为 status 看模式和后台，check 只恢复连接，usage 查本人用量。这三项不用重启 App。已登记本人第二中转时，用 other 切过去。original 兼容原入口，可能是第二中转，不一定是个人账号。

报错就把脱敏报错交回同一个 Agent，保留现场，不删除状态或重建密钥。个人包含本人 Key，不转发、不上传网页版 GPT。只停 SSH 不会恢复个人模式；旧对话不保证换线。

## 附录：本机 Agent 执行约定（必须读完再操作）

适用 Windows 原生 Codex **App**。App 内置 codex.exe 自报 CLI 版本是正常的，不按旧版本号阻断或强迫降级。原始发布标识：2026-09-12-r2，模式 schema 3。公开副本的隔离测试结果以仓库记录为准；Windows 原生桌面验收必须在本人电脑完成。

### r2：Store/AppX 普通用户“拒绝访问”修复

包内 WindowsApps 的 resources/codex.exe 可能可读却不可直接执行。安装器现在枚举 `%LOCALAPPDATA%\OpenAI\Codex\bin\<版本目录>\codex.exe`，仅接受与已安装包内后台 SHA-256 一致、无重解析路径的运行副本；优先使用当前会话正在运行的匹配版本。多版本无法确认则停止，不按日期选新旧、不执行任意 PATH/npm CLI。

核验通过显示 `APP_BACKEND_SOURCE=VERIFIED_RUNTIME_COPY`，随后仍进行本地模拟认证/Responses 兼容测试。不能把 --version 成功当 App 验收。无可信副本且包内路径不能执行时显示 `APP_BACKEND_EXECUTION_DENIED`；路径或哈希不匹配时显示 `APP_RUNTIME_UNVERIFIED`。不改 WindowsApps ACL、不提权、不降级、不重建密钥。

如果旧 repair 在这个 preflight 阶段失败、状态目录尚不存在且配置未改：先保留原包/有效恢复备份，再由本机 Agent 放好同一收件人的 r2 包（核对原公钥指纹与 Key 保持一致，不打印 Key），重新写入已验证的本机 python-path.txt。只重新执行 repair 并核对结果，未经本人确认不要自动执行 team。

### 先盘点、备份

- 核实实际桌面用户、执行 SID、是否提权、App 路径和版本；不照抄他人的 SID。最终运行用本人**普通 PowerShell**，不能为了 Agent 沙箱身份改 ACL，也不关闭 Codex 沙箱。
- 盘点用户主目录下的 .codex、.codex-sg-relay、Codex团队接入及重复安装。检查工作目录及祖先的 .codex/config.toml、App 启动参数、相关环境变量是否覆盖全局配置。只报告字段名、路径和冲突，不打印完整配置、token 或认证文件。
- 读取本包个人参数.json 的非敏感身份，匹配自己的公钥指纹和实际私钥路径，不重建密钥。管理员未确认开通则停止，不尝试 root、远程 shell 或其他成员账号。
- 查明原生 Windows CPython 3.11+ 的**绝对 python.exe 路径**；多个 Python 不猜。排除 MSYS2/Cygwin/WSL，确认 sys.platform=win32、os.name=nt、编译器为 MSC。在接入目录创建 python-path.txt，只写已验证路径一行（无引号，UTF-8 无 BOM）；也可本次显式设置 SG_RELAY_PYTHON。不擅自安装依赖或提权。
- 先备份实际全局配置和已有接入程序，保留已修好版本、原始快照和凭据。当前包放在用户主目录的 Codex团队接入，旧解压目录先改名备份，不覆盖身份不同的包。备份仅本人使用，不上传。

### 用当前入口收尾

**先区分安装类型，不能混用：**

- 标准 Python 旧包（状态内有 settings.json、切换CodexApp.py）：按下面 repair 增量升级，不删除状态。
- 现场 PowerShell/DPAPI 版（例如状态子目录有 bin/Codex-Mode.ps1）：当前入口会报 EXISTING_POWERSHELL_INSTALL 并保留现场。不要删除该目录来绕过检测。先审阅该脚本、manager、认证助手的代码和脱敏参数，沿用已有 check/个人入口恢复；这些源码未汇总前，不能宣称自动迁移成功。不要把其他人的修复脚本、SID、DPAPI blob 套进来。
- EFS_OR_REPARSE：核实包、状态及祖先目录是否加密/重定向。不要反复删 ACL 或执行批量解密；先确认一个本人可访问、未加密的位置与回退方案。

先执行准备命令，它校验能力、迁移完整旧状态或复用空目录，**不切换当前 App 配置、不启动后台**：

~~~powershell
& "$HOME\Codex团队接入\接入.cmd" repair
~~~

若 Agent 身份不同，交给用户在开始菜单打开的普通 PowerShell 执行同一行，不在沙箱里反复运行安装器。成功只报“配置准备完成”，再执行正文 team。

需要第二中转时，用 repair --other-provider 本人已有ID 登记经核实的本机提供商，不复制别人的配置。other 只切配置，不管理第二隧道。

程序只更新本套状态及根路由选择字段、sg_team 定义；变更前备份，事务失败回退，下次运行恢复未完成事务。并发变化、未知非空半安装、可信备份/Key 不匹配则停止。备份在 .codex-sg-relay\备份，新格式自动事务保留最近 10 份，历史备份不动。Windows 替换已有文件保留原文件 DACL，不按目录默认权限覆盖它。

### 已纳入程序的 Windows 修复要点

- 隔离本地模拟接口验证 App 后台 command auth / Responses 能力，不锁死 0.148；不消耗真实模型额度。
- 固定已登记的公开主机密钥并复核指纹，不依赖 ssh-keyscan 协商，不关闭主机校验。
- 比对本人执行 SID 与交互桌面身份。已有 ACL 只检查，不逐个删 ACE、不每次重写。接受本人/SYSTEM/管理员，以及系统确认的 Codex 沙箱组/成员的非写入权限；未知或可写额外权限停止审阅。仅新建状态目录初始化 ACL。
- 空状态可恢复；完整旧状态可带日志/锁文件迁移；未知半安装不当空目录。认证助手使用明确选定的原生 Python，凭据只在子进程管道内核验，不打印。
- 全局配置选择 sg_team、Responses 和受管认证助手，不把 Key 写进 TOML。personal 明确选择内置 openai 和 ChatGPT 登录，保留原登录。
- 模型偏好、项目、MCP/env 等非受管字段保留，不再要求与整份旧快照一致。modes.json 独立保存并校验 canonical；sg_team 丢失后可补回。未知根级包装、自定义 CODEX_HOME、个人账户地址覆盖仍须审阅。不编辑任务 JSONL/SQLite。
- team 入口在发现 App 内核版本/位置变化时重做本地模拟兼容测试；未变化不重复跑完整测试。它是执行入口时的检查，不是已经移植了管理员 Mac 的 App 启动 wrapper。
- HTTP 502/503/504 最多尝试 3 次、指数退避，不拆正常 SSH；401/403 立即认证失败。断网时运行中的维护器会尝试重连，能否恢复取决于网络、认证与进程状态；manager 与端口分别报告，不能把遗留 SSH 误报为后台完整健康。

### SSH 和前台修复

本套唯一服务器 203.0.113.10:22；默认本地 127.0.0.1:18318 → 远端 127.0.0.1:8317。使用自己的 SSH 用户与私钥。主机指纹：

SHA256:bbXpuKG6zhzdmnxq256TlqzFBzRl2f6OOg722cYNbU8

通常直接 team 管理后台。重复启动复用自身锁，不抢未知端口；日志在状态目录。无开机自启，不改 VPN、防火墙或其他隧道。

若 status 显示 worker=false、端口=true，说明可能是遗留 SSH 或其他占用，不能直接当成已恢复。先核实进程所属用户、完整参数和端口所有者；未确认前不接管、不结束。整个维护器退出后需运行原 check/team 入口，不能承诺靠不存在的后台自动恢复。

若已有实测通过的前台 SSH，先保留，不反复排查服务器或后台。可用 team --foreground 核实本人进程并切配置。它只接受以下严格形式；Agent 根据已核实状态填写变量，不能照抄占位符：

~~~powershell
ssh -F none -N -T -p 22 -i $verifiedKey -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 127.0.0.1:18318:127.0.0.1:8317 "$verifiedUser@203.0.113.10"
~~~

前台窗口需保持打开；脚本不杀它、不伪装成后台。转回日常后台前，请用户关闭这个已确认的前台窗口，再用 team 验证。不得终止无关进程。

### 本机验收与交付

分开验证本地模拟能力、SSH/API、团队 App 新对话、本人账号 App 新对话、重复启动。已证明 SSH/API 可用时不重复耗额度生成。CLI exec 成功不等于 App 通过。

请用户保存任务、完整重启 App，团队新对话发一次短测试；再切 personal、重启，以新对话确认本人账号和请求通道。不读取或输出登录凭据。最后恢复用户指定模式。尚未登录账号时让用户自己登录，此前该项记未验收。

每完成一阶段简短回报。最终给 CONFIG_MODE、LOCAL_CAPABILITY、SSH_API、REPEAT_START、TEAM_APP、PERSONAL_APP、OTHER_APP、FINAL，各项标 PASS / BLOCKED / NOT_RUN / NOT_APPLICABLE，并给首个阻塞点。未完成 Windows 实机验收不能给总 PASS；仅前台可用时明确后台未完成，不能宣布日常一行已完成。

速度独立验收：记录 SSH 建立时间、认证助手耗时（stdout 只接入内存，不打印）、models 耗时、一次短 Responses 首个输出与总耗时。先查旧证据，再最少量测试；不循环消耗额度。“接通”不等于“延迟已解决”。

## 给网页版 GPT 的上下文

> 我用 Windows Codex App，通过示例团队的本人 SSH 隧道接入，也要保留个人账号切换。请按上传的两份说明一步步协助，先识别现有安装和实际桌面身份，不反复重装、删 ACL 或重建密钥。每次只给一个必要操作，App 新对话实测前不宣布修好。我不会上传个人包、私钥、Key 或认证文件，请只索取脱敏输出。

只上传这两份说明和脱敏报错，保留同一网页对话。网页 GPT 无法直接操作本机，仍需本人执行核实后的命令。
